# ProxySwitch

ProxySwitch is a Windows launcher and session manager for running different apps through different proxy paths without changing the system proxy. It supports browser proxy profiles, generic application routing through ProxiFyre, and Store App routing through PID/session IPC.

## What It Does

- Launch Chrome or Edge with isolated user data directories and explicit proxy flags.
- Route selected desktop apps through local SOCKS5 endpoints using ProxiFyre.
- Route Store Apps through ProxiFyre PID sessions instead of global process-name rules.
- Track launched processes, child processes, handoff cases, and session restarts.
- Keep route decisions visible in the dashboard through sessions and events.

## Runtime Model

ProxySwitch is the user-facing WinForms app. ProxiFyre is a separate Windows service based on the upstream wiresock/proxifyre project.

```text
ProxySwitch (.NET 8 WinForms)
  -> launches apps and tracks sessions
  -> writes legacy ProxiFyre config for generic exe routes
  -> sends Store App PID routes through named-pipe IPC

ProxiFyre (C++/CLI + C# service, .NET Framework 4.7.2)
  -> captures TCP/UDP traffic through Windows Packet Filter / NDISAPI
  -> maps process names for legacy routes
  -> maps runtime PIDs for Store App sessions
```

Named pipe used by v1.0 PID/session routing:

```text
\\.\pipe\ProxySwitch.ProxiFyre.SessionRoute
```

## Requirements

- Windows 10/11.
- .NET 8 Runtime for running ProxySwitch.
- .NET 8 SDK for building ProxySwitch.
- Visual Studio 2022 Build Tools with C++/CLI support for building ProxiFyre.
- .NET Framework 4.7.2 Developer Pack for ProxiFyre.
- Windows Packet Filter driver for ProxiFyre runtime traffic capture.
- Local SOCKS5 endpoints, for example `127.0.0.1:10708`, `127.0.0.1:10608`, or `127.0.0.1:10808`.

See [localCompile.md](localCompile.md) for exact local tool paths and build commands.

## Basic Usage

1. Start the local proxy backend you want to use, such as Clash Verge or v2ray.
2. Start or install the ProxiFyre service if transparent per-app routing is needed.
3. Run `ProxySwitch.exe`.
4. Use the dashboard to launch pinned apps or drag an `.exe` into a route zone.
5. Watch the `Sessions` and `Events` panes for routing status.

Browser sessions use command-line proxy flags. Generic desktop apps use ProxiFyre config-file routes. Store Apps use named-pipe IPC and PID routing.

## Configuration

Main user config:

```text
config/proxyswitch.json
```

Important sections:

- `proxies`: named SOCKS5 endpoints such as `p10708`, `p10608`, `p10808`.
- `apps`: pinned launch targets and browser profiles.
- `transparentBackend`: ProxiFyre executable, app-config path, service name, and restart policy.
- `appRoutes`: persistent legacy ProxiFyre routes for explicit desktop apps.
- `sessionSupervisor`: grace-window handling for process restarts and reattach.

Runtime ProxiFyre config:

```text
backend/proxifyre/app-config.json
```

This file is generated by ProxySwitch. Do not manually add broad rules such as `codex.exe`, `git.exe`, `python.exe`, `powershell.exe`, or `conda.exe`; they pollute unrelated sessions.

ProxySwitch:

```powershell

& 'C:\Users\MUSHI\AppData\Local\Microsoft\dotnet\dotnet.exe' build ProxySwitch.csproj
```

